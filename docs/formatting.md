# Оформление

## Markdown

- Используйте один заголовок первого уровня на странице.
- Повышайте уровень заголовка последовательно.
- Отделяйте заголовки, списки и блоки кода пустыми строками.
- Используйте дефис для маркированных списков и числа для последовательных шагов.
- Оформляйте команды, имена файлов и значения параметров как inline code.
- Заключайте многострочный код в fenced code block и указывайте язык.

## Ссылки

Текст ссылки должен описывать назначение. Не используйте формулировки «нажмите здесь» и «подробнее» без контекста.

Плохо: «Подробнее нажмите здесь».

Лучше: «См. руководство по установке».

## Изображения

Добавляйте изображение, только если оно помогает понять действие или результат. Всегда задавайте краткий alt-текст, а сложное изображение поясняйте рядом с ним.

```markdown
![Форма настройки профиля](images/profile-settings.png)
```

## Команды и имена файлов

В предложении оформляйте команды и имена файлов как inline code: выполните `mkdocs serve` и откройте `mkdocs.yml`. Отдельный блок используйте для команды с параметрами или нескольких строк.

## Элементы интерфейса

Названия кнопок, вкладок и полей выделяйте полужирным начертанием: нажмите **Сохранить**, затем откройте вкладку **Профиль**. Записывайте название так, как оно показано в интерфейсе.

## Примечания и предупреждения

Примечание содержит дополнительную полезную информацию, без которой действие обычно можно выполнить.

> **Примечание.** Локальный сервер автоматически обновляет страницу после изменения файла.

Предупреждение сообщает о возможной ошибке, потере данных или другом важном последствии. Используйте его только тогда, когда читателю действительно нужно остановиться и оценить риск.

> **Предупреждение.** Удаление учётной записи нельзя отменить.
